# Space Whiskers: The Holy Cow: notes

**The game.** The remake of Space Mouse, made fresh: a side-view platformer about Pip, a mouse astronaut, in a universe run by cats, on a
quest tied to Stellamoo, the Holy Cow. This folder is its working folder (the owner, 2026-11-16). There is no game code yet (no `game.json`,
so the build and the site skip the folder); the art and the story come first.

**The scale (the owner's rule).** "I really want the resolution of the game to be what these images are. I want that to be the scale of the
whole game." The grid of the sprite sheet `ref/pip.png` is the game's: one of its art pixels (2.86 picture pixels) is one game pixel, for
every sprite, prop and tile alike. Pip stands **49 game pixels** tall and is drawn and shown 1:1 (k .5, not halved as Space Mouse's Pip is).
The **screen is 480 x 270** game pixels (the owner: "a notch bigger. We don't have to follow SNES 1:1, but still keep the screen small"): 16:9,
a quarter of 1080p each way, so every game pixel is exactly 4 x 4 screen pixels on a 1080p monitor (8 x 8 on 4K); Pip is a fifth of its height
(5.5 of him tall). The sprite sheet itself is about 380 x 213 game pixels (384 x 216 was the first idea). Written into `art/style/style.json`.
The level picture `ref/levelinspiration.png` is a **zoomed-out overview** (the owner, 2026-11-16: "the level inspiration should be seen as
a bit zoomed out. The actual gameplay should be a smaller frame"): Pip is about 70 of its pixels tall, so one 480 x 270 game screen covers about
686 x 386 of it, about two thirds of its width and height. Levels are drawn at the sprite sheet's scale; the picture shows what they look
like, not how much of them fits on a screen.

```
  levelinspiration.png the Whiskerworks shipyard: the look of a level
  levelinspirationprops.png  props on green (platforms, girders, pipes, machines, crates, signs, cats, ship parts): not cut yet
  StarWhiskers-theholycow_cover.png  the cover (its title still reads "Star Whiskers")

                     Swedish originals, FEEDBACK.md, COVER_PROMPT.md, CHAPTER_COVERS.md
art/                 the art pipeline (docs/ART_PIPELINE.md)
  style/               style.json (the scale, the classes, the style paragraph), palette.json (32 colours of Pip's drawings)
  assets/pip/          Pip on the game grid, 57 x 54 canvas, feet on the bottom row: 13 frames from the sheet (idle, walk1-4,
                       run1-4, slide, crouch, jump, wall_slide), versions 001-013, kind "imported"
  anims/pip-walk.json  Pip's walk: the rig fitted to the idle frame, PixelLab's joint map, the sheet's 4 walk frames as keys of 8
  anims/pip-run.json, pip-idle.json, pip-jump.json   the run (8), idle (4) and jump (8, once): the walk's rig (rigFrom), their own poses
  bakeoff/<anim>/      the drafts, one folder per method, compare.png, preview.gif, report.md; PixelLab's (the owner's pick) in pixellab-skeleton/
pipeline.js          generated by node tools/art.mjs build spacewhiskers (PIPE_ART.pip with its frames)

tools/frames.mjs     brings the cut drawings onto the game grid: one pixel size, one palette, registered, into art/assets/pip
```

## Commands

```sh
python3 games/spacewhiskers/tools/art.py                       # cut the sheet again (after a new ref picture)
node games/spacewhiskers/tools/frames.mjs --dry                # what the frames come to on the game grid
node tools/art/bakeoff.mjs spacewhiskers pip-walk --dry        # the guides and prompts, no calls
node tools/art/bakeoff.mjs spacewhiskers pip-walk --methods sheet-keys,pixellab-skeleton,toon-inbetween,wan-segments
node tools/art/bakeoff.mjs spacewhiskers pip-walk --compare    # the sheet and report again, free
node tools/art.mjs check spacewhiskers                          # the art folder is consistent
```

## Animations

How they are drafted, and why, is in `docs/ANIMATION.md`. In short: the owner's drawings are the approved keys; models draft the frames
between them (Wan 2.7 between two keys, ToonCrafter through all of them) or redraw the base sprite from the rig (PixelLab); the tools snap
every frame to the game grid and palette, register it (feet on the ground, helmet over the idle's) and measure it; the owner picks.

**The workflow for each animation**: pose the keys (`art/anims/<anim>.json`), look at `bakeoff/<anim>/guides/rig.gif` (written by
`node tools/art/bakeoff.mjs spacewhiskers <anim> --dry`), the owner approves the motion (`"rigApproved": true`), then PixelLab draws it
(`--methods pixellab-skeleton`); the drawing methods refuse an unapproved rig. Approved so far: the walk's rig.
